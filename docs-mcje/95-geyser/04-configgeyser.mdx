## 首次加载Geyser？

如果你是首次加载Geyser,请等待它把语言文件之类的下载完成。

![说明图片](/img/pages/mcje/configgeyser-1.png)

_**这里演示的是插件版本**_

在你的服务器根目录文件找到plugins 

![说明图片](/img/pages/mcje/configgeyser-2.png)

然后找到配置文件夹(Geyser-xxx)

"xxx"是你的服务端类型,这里使用的是 Paper 服务端，Spigot 的下游服务端，文件夹名为 `Geyser-Spigot`

![说明图片](/img/pages/mcje/configgeyser-3.png)

:::tip[温馨提示]
不同的类型的 Geyser 这个文件夹名字会不一样   
比如 Fabric 的是 `Geyser-Fabric`   
以及如果你是 Fabric 和 Neoforge 服务端，配置文件夹在服务器根目录的 config 文件夹内。
:::

## 配置文件(config.yml)

![说明图片](/img/pages/mcje/configgeyser-4.png) 

配置方面基本只要留意这个文件

![说明图片](/img/pages/mcje/configgeyser-5.png)

```yaml title="config.yml"
# --------------------------------
# Geyser 配置文件
# 
# 一个用于连接 Minecraft：基岩版与 Minecraft：Java 版的桥接工具。
# 
# GitHub：https://github.com/GeyserMC/Geyser
# Discord：https://discord.gg/geysermc
# Wiki：https://geysermc.org/wiki
# 
# 注意：请参阅 https://geysermc.org/wiki/geyser/setup/ 获取安装指南。许多视频教程已经过时。
# 在大多数情况下，尤其是使用服务器托管服务商时，还需要进行特定于托管服务商的进一步配置。
# --------------------------------

# 用于监听基岩版连接的网络设置
bedrock:
  # Geyser 绑定用于监听传入基岩版连接的 IP 地址。
  # 通常，只有当你希望限制可连接到服务器的 IP 时才需要更改此项。
  address: 0.0.0.0

  # Geyser 用于监听传入基岩版连接的端口。
  # 内置信令在 TCP 上使用此端口（如果未设置“webrtc-port”，也使用 UDP），而 RakNet 在 UDP 上使用此端口。
  port: 19132

  # 用于 NetherNet 连接的 UDP 端口。设置为 0 时，Geyser 使用上面的“port”值。
  # 玩家会直接连接到此端口，因此如果在路由器后面，请转发该端口。使用“nxs”信令且关闭 assisted-joins 时，
  # 否则玩家将无法连接。
  webrtc-port: 0

  # 基岩版玩家如何连接。更改需要重启。
  # “nethernet”：基岩版的新连接方式。它需要信令，请参见下面的“signaling”。
  # “both”：同时接受 NetherNet 和 RakNet。每种方式都需要自己的 UDP 端口，请参见“port”和“webrtc-port”。
  # “raknet”：旧连接方式。基岩版将在未来版本中停止支持它。
  transport: raknet

  # 一些托管服务每次启动服务器时都会更改你的 Java 端口，并要求基岩版使用相同端口。
  # 此选项使每次启动服务器时基岩版端口都与 Java 端口相同。
  # 如果你使用此选项，则需要一个额外的信令端口，或使用 NXS 作为信令，因为信令不能与 Java 服务器共享端口。
  clone-remote-port: false

  # 信令是基岩版玩家找到此服务器，以与其建立 NetherNet WebRTC 连接的方式。
  # 仅在“nethernet”和“both”传输方式下使用。更改需要重启。
  signaling:
    # 使用 NetherNet 时，基岩版玩家如何找到此服务器。
    # “builtin”：Geyser 在基岩版端口上通过 TCP 运行自己的信令服务器。如果 Java 服务器使用相同端口
    # （例如使用“clone-remote-port”），则此方式无效。在这种情况下，Geyser 会自动回退到“nxs”。
    # “nxs”：Geyser 将此服务器注册到下面“nxs.endpoint”中配置的外部信令服务。
    # “hybrid”：同时使用“builtin”和“nxs”。
    mode: builtin

    # 内置信令和外部信令都会向连接的玩家发送用于 NetherNet WebRTC 连接的地址，
    # 例如 play.example.com、198.51.100.1 或 [2001:db8::1]:19133。如果未给出端口，则使用 NetherNet UDP 端口。
    # 主机名会在信令启动时解析；如果无法解析，则信令不会启动。
    # 你可以列出此机器并不拥有的地址，例如你的公网 IP，只要你的路由器将该端口转发到此机器。
    # 你需要自行设置端口转发。
    # 留空则使用此机器自身的地址，以及通过“stun-discovery”找到的公网地址。
    advertise-addresses: []

    # 当“advertise-addresses”为空时，通过 STUN 查找此服务器的公网地址。
    # 内置信令会询问公共 STUN 服务器，外部信令服务则会询问它自己的 STUN。
    stun-discovery: true

    # 内置信令的设置。仅在“builtin”和“hybrid”模式下使用。
    builtin:
      # 通过 HTTPS 提供内置信令的设置。配置后，HTTP 将被拒绝。
      https:
        # TLS 证书路径。可以是 PEM 证书链（将其密钥放在“private-key”中），
        # 也可以是 PKCS12 文件（将“private-key”留空）。
        # 通过 HTTPS 连接的玩家不会看到“首次使用信任”提示。
        # 留空则仅使用 HTTP。
        certificate: ''

        # “certificate”的 PEM 私钥路径。如果“certificate”是 PKCS12 文件，则留空。
        private-key: ''

        # PKCS12 文件的密码，或加密 PEM 私钥的密码。如果没有密码则留空。
        # 你也可以使用“file:/path/to/password”从文件读取密码，这比直接写在这里更安全。
        password: ''

    # 外部信令服务的设置。仅在“nxs”和“hybrid”模式下，或内置信令无法运行时使用。
    nxs:
      # 信令服务的访问令牌，或 file:/path/to/token 以从文件读取。留空则以无账户方式注册。
      token: ''

      # 外部信令服务（NXS）的地址。
      endpoint: https://agent.warden.cloud

# Java 服务器连接的网络设置
java:
  # 基岩版玩家登录 Java 服务器时，将使用哪种类型的身份验证进行检查。
  # 可以是“floodgate”（参见 https://wiki.geysermc.org/floodgate/）、“online”或“offline”。
  auth-type: online

# MOTD 设置
motd:
  # 将向 Minecraft：基岩版客户端广播的 MOTD。如果“passthrough-motd”设置为 true，则此项无关紧要。
  # 如果其中任一字符串为空，则相应字符串将默认为“Geyser”
  primary-motd: Geyser
  secondary-motd: Another Geyser server.

  # Geyser 是否应将 Java 服务器的 MOTD 转发给基岩版玩家。
  passthrough-motd: true

  # 可连接的最大玩家数量。
  # 这仅是视觉效果，并且仅在禁用 passthrough-motd 时生效。
  max-players: 100

  # 是否将 Java 服务器的玩家数量和最大玩家数量转发给基岩版玩家。
  passthrough-player-counts: true

  # 是否使用服务器 API 方法来确定 Java 服务器的 MOTD 和 ping 转发。
  # 除非你的 MOTD 或玩家数量显示不正常，否则无需禁用此项。
  integrated-ping-passthrough: true

  # 以秒为单位，多久 ping 一次 Java 服务器以刷新 MOTD 和玩家数量。
  # 仅在禁用 integrated-ping-passthrough 时相关。
  ping-passthrough-interval: 3

# 影响基岩版玩家的游戏玩法选项
gameplay:
  # 将发送给 Minecraft：基岩版客户端的服务器名称。此名称在暂停菜单和设置菜单中都可见。
  server-name: Geyser

  # 允许发送一个假的冷却指示器。否则基岩版玩家看不到冷却，因为他们仍使用 1.8 战斗机制。
  # 请注意：在禁用集成资源包的情况下，一些用户可能会在冷却序列期间看到黑框，如下所示：
  # https://geysermc.org/img/external/cooldown_indicator.png
  # 可以通过启用集成资源包，或在基岩版设置的辅助功能选项卡中将“文本背景不透明度”设置为 0 来解决此问题。
  # 此设置可设置为“crosshair”、“hotbar”或“disabled”
  cooldown-type: crosshair

  # 如果向基岩版客户端提供大量命令，首次打开命令提示符时客户端可能会冻结。
  # 禁用此项将阻止发送命令建议，并解决基岩版客户端冻结的问题。
  command-suggestions: true

  # 控制是否向玩家显示坐标。
  show-coordinates: true

  # 是否阻止基岩版玩家进行其脚手架式搭桥。
  disable-bedrock-scaffolding: false

  # 基岩版阻止在下界 Y127 以上建造和显示方块。
  # 此配置选项通过将下界维度 ID 更改为末地 ID 来绕过该限制。
  # 主要缺点是整个下界将具有相同的红色雾气，而不是每个生物群系有不同的雾气。
  nether-roof-workaround: false

  # 是否向其他基岩版玩家显示基岩版表情动作。
  emotes-enabled: true

  # 是否移除基岩版玩家发送的旧版文本格式代码。
  # 与 Java 版不同，在基岩版中可以输入用于旧版颜色代码的节符号。
  # 更多信息请参见 https://minecraft.wiki/w/Formatting_codes。
  block-legacy-codes: true

  # 用于标记基岩版玩家物品栏中不可用槽位的物品。例如创造模式下的 2x2 合成格，
  # 或大小不同于通常 3x9 的自定义物品栏菜单。默认物品是屏障方块。
  # 此配置选项可设置为任何基岩版物品标识符。如果要将其设置为自定义物品，请确保按以下格式指定物品："geyser_custom:<mapping-name>"
  unusable-space-block: minecraft:barrier

  # 是否添加基岩版中通常不存在的任何物品和方块。
  # 只有在使用不使用“transfer packet”风格服务器切换的代理时，才可能需要禁用此项。
  # 如果禁用此项，熔炉矿车物品将映射为漏斗矿车物品。
  # Geyser 的方块、物品和头颅映射系统也将被禁用。
  # 此选项需要重启 Geyser 才能更改其设置。
  enable-custom-content: true

  # 如果有任何资源包，强制客户端加载所有资源包。
  # 如果设置为 false，则允许用户即使不想下载资源包也可以连接到服务器。
  force-resource-packs: true

  # 是否自动向所有连接的基岩版玩家提供 Geyser 某些功能所需的资源包。
  # 如果启用，force-resource-packs 将被启用。
  enable-integrated-pack: true

  # 是否将玩家 ping 转发到服务器。启用此项可以让基岩版玩家拥有更准确的 ping，
  # 但也可能导致玩家更容易超时。
  forward-player-ping: false

  # 允许解锁 Xbox 成就。
  # 如果玩家输入未知命令，他们将收到一条消息，说明作弊已禁用。
  # 否则，命令会按预期工作。
  xbox-achievements-enabled: false

  # 每位玩家最多显示的自定义头颅数量。增加此值可能会降低较弱设备的性能。
  # 值为 0 将禁用所有自定义头颅。
  # 将此设置为 -1 将导致无论距离或数量如何都显示所有自定义头颅。
  max-visible-custom-skulls: 128

  # 显示自定义头颅的玩家周围半径（以方块为单位）。
  custom-skull-render-distance: 32

# 如果我们没有客户端请求的默认语言环境，则使用此默认语言环境。如果设置为“system”，将使用系统语言。
default-locale: system

# 服务器是否记录玩家 IP 地址。
log-player-ip-addresses: true

# 仅用于 online 模式身份验证类型。
# 存储在登录后应保存其 Java 版账户的基岩版玩家用户名列表。
# 这会保存一个令牌，之后可用于重新验证玩家。这不会保存电子邮件或密码，
# 但在添加到此列表并允许他人访问此 Geyser 实例的文件时，你仍应谨慎。
# 从列表中移除某个名称将在下次 Geyser 启动时删除其缓存的登录信息。
# 令牌将保存在与此配置相同文件夹中的文件中，文件名为“saved-refresh-tokens.json”。
saved-user-logins:
  - ThisExampleUsernameShouldBeLongEnoughToNeverBeAnXboxUsername
  - ThisOtherExampleUsernameShouldAlsoBeLongEnough

# 仅用于 online 模式身份验证类型。
# 指定在用户授权 Geyser 访问其 Microsoft 账户时等待多少秒。
# 允许用户在此期间断开连接。
pending-authentication-timeout: 120

# 是否在控制台和操作员中提醒有新的 Geyser 版本可用，该版本支持此 Geyser 版本不支持的基岩版版本。
# 建议保持启用此选项，因为许多基岩版平台会自动更新。
notify-on-new-bedrock-update: true

# 高级配置选项。通常不需要修改。
advanced:
  # 指定玩家皮肤图像将缓存到磁盘多少天，以节省从互联网下载它们。
  # 值为 0 表示禁用。（默认：0）
  cache-images: 0

  # Geyser 会在每个 Scoreboard 数据包后更新记分板，但当 Geyser 尝试每秒处理
  # 大量记分板数据包时，这可能导致严重卡顿。
  # 此选项允许你指定每秒多少个记分板数据包后，
  # 将记分板更新限制为每秒四次更新。
  scoreboard-packet-threshold: 20

  # Geyser 是否应在命令建议中发送队伍名称。
  # 如果你有许多不需要作为建议的队伍，请禁用此项。
  add-team-suggestions: true

  # 要发送给基岩版客户端下载的远程资源包 URL 列表。
  # 基岩版客户端对这些内容的传输方式非常挑剔——更多信息请参见我们的 wiki 页面：https://geysermc.org/wiki/geyser/packs/
  resource-pack-urls: []

  # Floodgate 使用加密来确保仅从授权来源使用。
  # 此项应指向 Floodgate 生成的公钥（BungeeCord、Spigot 或 Velocity）
  # 不使用 Floodgate 时你可以忽略此项。
  # 如果你在同一服务器上使用 Floodgate 的插件版本，密钥将自动从 Floodgate 获取。
  floodgate-key-file: key.pem

  # Geyser 到 Java 服务器连接的高级网络选项
  java:
    # 连接到 Java 服务器时是否启用 HAPROXY 协议。
    # 仅在以下情况下有用：
    # 1）你的 Java 服务器支持 HAPROXY 协议（它可能不支持）
    # 2）你在代理的主配置中启用了该选项并运行 Velocity 或 BungeeCord。
    # 如果你不知道这是什么，请不要改动它！
    use-haproxy-protocol: false

    # 是否在不创建 TCP 连接的情况下直接连接到 Java 服务器。
    # 只有在与数据包或网络交互的插件无法与 Geyser 正常工作时才应禁用此项。
    # 如果启用，remote address 和 port 部分将被忽略。
    # 如果禁用，预计性能会下降，延迟会增加。
    use-direct-connection: true

    # Geyser 是否应尝试为基岩版玩家禁用数据包压缩（从 Java 服务器到 Geyser）。
    # 这应该是有益的，因为当 Java 数据包不通过网络处理时，无需压缩数据。
    # 这要求 use-direct-connection 为 true。
    disable-compression: true

  # Geyser 基岩版监听器的高级网络选项
  bedrock:
    # 通过 MOTD 向基岩版客户端广播的端口，告诉他们应使用该端口连接到服务器。
    # 值为 0 将广播上面指定的端口。
    # 除非 Geyser 运行的端口与用于连接的端口不同，否则不要更改此项。
    # 此选项对 NetherNet 不再相关，并将在 RakNet 不再受支持后移除。
    broadcast-port: 0

    # 向基岩版客户端压缩网络流量的程度。数值越高，CPU 使用越多，但
    # 使用的带宽越小。低于 -1 或高于 9 没有任何效果。设置为 -1 可禁用。
    compression-level: 6

    # 是否期望连接基岩版客户端时使用 HAPROXY 协议。
    # 仅当你在 Geyser 实例前面运行反向代理时有用。
    # RakNet：不发送 HAPROXY 头的客户端将被忽略。
    # 内置信令：仅从“haproxy-protocol-whitelisted-ips”中列出的代理读取 HAPROXY 头。
    # 没有该头的连接仍会被接受。
    # 如果你不知道这是什么，请不要改动它！
    use-haproxy-protocol: false

    # 允许的会说 HAPROXY 协议的代理 IP 地址/子网列表。仅在启用“use-haproxy-protocol”时有效。
    # 保持此列表为空意味着对发送 HAPROXY 头的连接没有 IP 地址白名单。
    # 内置信令仅从此列表中的代理读取 HAPROXY 头，因此列表为空时它不读取任何头。
    # 此列表中的代理也不受内置信令的每地址连接限制影响。
    # 支持 IP 地址、子网和纯文本文件链接。
    haproxy-protocol-whitelisted-ips: []

    # 内置信令前面的反向代理地址列表（例如 HTTP 负载均衡器）。
    # 内置信令从“X-Forwarded-For”头读取玩家的真实地址，并且不会对所有列出的代理
    # 应用其每地址连接限制。这与 HAPROXY 协议是分开的。
    # 支持 IP 地址、子网和纯文本文件链接。
    signaling-trusted-proxies: []

    # 如果此 Geyser 实例位于 WaterdogPE 代理后面，应启用此项。如果启用，Geyser 将
    # 使用 WaterdogPE 发送的 xuid / address，并拒绝不发送它们的客户端。
    use-waterdogpe-forwarding: false

    # 互联网支持的最大 MTU 为 1492，但可能导致数据包分片问题。
    # 1400 是默认值。
    mtu: 1400

    # 此选项禁用 Geyser 为连接基岩版玩家执行的身份验证步骤。
    # 可用于允许来自 ProxyPass 和 WaterdogPE 的连接。在这些情况下，请确保用户
    # 无法直接连接到此 Geyser 实例。请参阅 https://www.spigotmc.org/wiki/firewall-guide/ 获取
    # 帮助——并使用 UDP 而不是 TCP。
    # 不建议为其他用例禁用基岩版身份验证，因为这允许任何人伪造用户名，因此存在安全风险。
    # 当此选项禁用时，所有 Floodgate 功能（包括皮肤上传和账户链接）也将无法工作。
    validate-bedrock-login: true

    # 是否记录 NetherNet 的调试消息，来自 libdatachannel 和 NetherNet 本身，例如信令
    # 和 STUN 发现做了什么。当玩家无法通过 NetherNet 连接时很有用。
    nethernet-debug: false

  # 外部信令服务的高级选项。仅在“nxs”和“hybrid”信令模式下使用。
  nxs:
    # 让信令服务在玩家无法直接到达此服务器时帮助玩家连接，
    # 例如服务器位于没有端口转发的 NAT 后面时。
    assisted-joins: false

    # 让信令服务从多个区域检查玩家是否可以到达此服务器，
    # 并停止提供失败的地址。
    connection-checks: true

    # 此服务器所在位置：“country”（两位字母代码）、“city”、“latitude”和“longitude”。
    # 留空以让信令服务估计或配置它。
    location: {}

    # 当 Geyser 关闭时，从信令服务中移除此服务器。
    # 如果“nethernet”文件夹在每次重启时都会丢失（例如在没有卷的容器中），请启用此项。
    # 否则，每次重启都会将此服务器重新注册为一个新服务器。
    deregister-on-shutdown: false
```
