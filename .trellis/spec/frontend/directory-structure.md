# Directory Structure

> Current frontend and content architecture.

---

## Overview

The site is a statically exported Next.js App Router application. Fumadocs supplies the documentation renderer, search, page tree, LLM views, and OG image pipeline. Legacy documentation remains authoritative and is copied unchanged into the Fumadocs content directory.

## Module Organization

- `src/app` owns routes, static export metadata, and generated static parameters.
- `src/components` owns reusable UI and MDX component mapping.
- `src/lib` owns Fumadocs source construction, shared constants, licensing, and LLM metadata.
- `src/assets/fonts` owns the bundled font subset used by static OG image generation.
- `scripts` owns repeatable migration, verification, EdgeOne generation, and post-build cleanup.
- `content/docs` owns documentation body content and generated Fumadocs metadata.
- `src/proxy.ts` is available during local Next.js development, but static export disables middleware; production Markdown views must use explicit `/llms.mdx/*` links.

## Naming Conventions

- Keep legacy document file names, numeric prefixes, frontmatter, and admonition syntax unchanged.
- Use App Router route groups only for presentation boundaries; docs routes are unified under `/docs`.
- Place page-specific components near their route only when they are not reusable; otherwise use `src/components`.
- Keep shared site values in `src/lib/shared.ts`.

## Generated And Ignored Files

- `.source/` is generated by Fumadocs MDX and must not be edited.
- `.next/` and `out/` are build outputs.
- `migration/legacy-routes.json`, `migration/generated-routes.json`, and `migration/legacy-content-manifest.json` are committed audit baselines.
- Generated `meta.json` files may be regenerated by the migration script, but legacy source files must remain byte-for-byte unchanged.
